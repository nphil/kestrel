# Kestrel dashboard

Lit 3 + strict TypeScript, bundled by esbuild into `../custom_components/kestrel/frontend/kestrel.<hash>.js`
(budget: 80 KB gzipped; the build fails above it; about 75 KB today).

## Fixture harness (`dev/`)

`dev/harness.ts` mounts the real `kestrel-panel` the way Home Assistant does: `dev/ha/` holds an `ha-panel-custom` stand-in (gives the panel `hass`,
`narrow` (<= 870 px), `route`, `panel`; pads it by the safe-area insets; offers `navigate()`; destroys the panel when the address leaves `/kestrel` and
creates a new one when it comes back), the sidebar frame (docked 256 px above 870 px, otherwise a drawer opened by `hass-toggle-menu`; `hass-kiosk-mode`),
`ha-icon`/`ha-card`/`ha-form` stand-ins (the form only proves a card editor writes the right settings; Home Assistant's own form looks different), and Home Assistant's real Neumorphism / Frosted Glass theme data (copied from lucent-ha's `dev/`, MIT). `hass` is immutable:
every change (connection, theme, sidebar, kiosk) builds a new object.

Address parameters (read on the first load, kept for the tab, removed from the address): `?theme=flat-light|flat-dark|glass-light|glass-dark`
(default `flat-light`), `toolbar=1` (small button bar), `sidebar=docked|auto|always_hidden`, `kiosk=1`, `safe=top,right,bottom,left` (px), `latency=ms`
(fake server delay, default 40), `epoch=N`. The wildlife features have their own: `quiet=1` (nothing has come yet today, so "Today" is empty), `fail=period,highlights,recordings`
(those questions fail), `spectrogram=trouble` (the pictures under the recordings go wrong in turn: not ready the first time, failing, slow, never drawn),
`cards=1` (`/kestrel/cards` shows the two Kestrel cards laid out like a dashboard, with their editors; every other address under `/kestrel` still shows the panel).
The made-up species history, descriptions, highlights, weather and spectrograms come from `dev/wildlife-fixtures.ts`; `dev/serve.mjs` answers spectrogram pictures after 600 ms
(an id starting `blank-` is never drawn and answers 204, `err-` answers 504, `flaky-` answers 204 the first time and the picture after, `slow-` takes 8 seconds).

`window.__ha` drives it: `setTheme(name)`, `disconnect()`, `reconnect()`, `restart({ downMs = 1500 })` (epoch + 1, socket drops now, returns after
`downMs`), `rotateKey()` (epoch + 1, the socket stays up and nothing announces it), `epoch`, `hass`, `theme`, `subscriptions`, `setSidebar(mode)`, `setKiosk(bool)`. `window.__emit({ type, data })` pushes an event as the
integration would. While the socket is down `callWS` fails like home-assistant-js-websocket (bare `3` for a new call, `{ code: 3, message: "Connection lost" }`
for one in flight). Media links are `/api/kestrel/media/<kind>/<id>?authSig=e<epoch>`; links already handed out keep their epoch, so a test's request
interceptor can answer 401 for the old ones, as a restarted Home Assistant does (`window.__setEpoch(epoch)` is called when it is defined).

failure; screenshots in `/tmp/kestrel-smoke/`). Run them as `taskset -c 0-4,8-12 nice -n 15 node dev/smoke/<script> --size 390x844`:

## Layout

The panel is built on the shared toolkit [lucent-ha](https://github.com/nphil/lucent-ha) (`package.json` pins a release tag): the app shell (pinned bar,
menu button, navigation that follows the panel's size), view stack (each tab keeps its scroll), sheet, image, audio list and the rest come from it,
registered once under the `kestrel-lu-` prefix in `src/main.ts`. Colours, spacing and motion are `--lu-*` tokens that follow the live Home Assistant theme.

- `src/components/` Kestrel glue: the panel (`kestrel-cameras`), the species sheet, the live player, and the "Play reference" block (`kestrel-reference-sound`: what a species sounds like, from Xeno-canto or iNaturalist, played through signed Home Assistant links; nothing is asked until it is pressed).
- `src/ui/` the few Kestrel-only building blocks: self-refreshing live picture, the heard-visit hero.
- `src/detections.ts` the maths of the detection boxes on a visit video, plain functions with no page; `src/components/kestrel-detection-boxes.ts` draws them (see below).
- `src/recovery.ts` + the recovery code in `kestrel-cameras`: after Home Assistant restarts its signed media links stop working; the panel asks the server
  about one link, and if it is refused it drops every saved link, asks for fresh data and re-creates the audio players. Nothing is reloaded.
- `src/styles/panel.ts` the panel's own styles (tokens only).
- `src/vocab.ts` the single icon and word for "on camera" (video), "heard" (waveform) and a library "reference" recording (book and note, never the waveform), used everywhere.

## Detection boxes on the visit video

The plugin keeps what the wildlife detector saw while a camera clip was recorded and sends it with a visit (`visit.detections`: when the clip starts, an offset, and a list of detections, each with boxes given as shares of the picture). It is on the answer for one visit only (not in lists or events) and only while the clip is ready. Where it is, the clip gets a round button at its top right (icon `mdi:select`, named and titled "Show detection boxes", `aria-pressed`, filled with the accent while on). Turned on, a box follows each animal through the clip with a one-line name chip: the species once the classifier named it (with a percentage only when it sent one), otherwise "Animal 82%" (the detector's own score, never put next to a species). Pressing a box or its chip opens the same "What was it?" picker as "Wrong?". The choice is kept in `localStorage` (`kestrel.detection-boxes`, off until chosen) and holds for every visit page.

- **In step with the video.** `requestVideoFrameCallback`'s `mediaTime` says which moment is on screen (a browser without it: animation frames while the clip plays, plus `timeupdate`). A detection at wall-clock time `t` belongs to video time `t + offsetMs - clipStartAt`, so a positive offset means the video runs behind the detector. Between two detections at most 700 ms apart a box slides from one to the other (the detector's id says which box is which, else the closest centre; a label comes from the closer detection); within 400 ms of a detection a box is held, further it is not drawn; with reduced motion the closer detection is drawn as it is, so boxes step. Positions are written straight to a few elements for every frame, with no Lit render while the clip plays. Nothing is drawn or waited for while the boxes are off, the video is out of sight or the tab is hidden, and every listener, observer and callback goes when the page or the visit does.
- **Letterboxing.** The clip sits in a 16:10 `object-fit: contain` element, so a 16:9, 4:3 or portrait picture has empty bands; boxes are placed on the picture inside it (`containRect`), at every width and after every resize.
- **The video's own controls keep working.** The box layer takes no press (`pointer-events: none`) except on a box, a box's tap area stops 76 px above the bottom of the video (`CONTROLS_PX`: measured on Chromium's controls, phone and desktop alike, the timeline takes the lowest 24 px and the buttons above it reach 73 px up) and lies under the on/off button, so a press there reaches the controls or the button; a press on the empty picture plays and pauses as before. Labels keep out from under the button. The boxes are `aria-hidden` (the "Wrong?" button is the way in for a screen reader); the button is a real button. The browser's own full-screen mode shows the video alone, without boxes.
- **Where things are.** `src/detections.ts` (`boxesAt`, `boxLabel`, `containRect`, `toPixels`, `placeLabel`, `hitRect`, `readDetections`, `keepTrack`) is held by `test/detections.test.mjs`; `src/api.ts` lets a track through only as far as `readDetections` can use it; `src/components/kestrel-detection-boxes.ts` wraps the `<video>` on the visit page and draws. A fresh answer for the visit on screen that has no track of its own (a seed from a list, an answer that could not read it) keeps the old one.
- **In the harness.** `fixture-visit-1` (open `/kestrel/visit?v=fixture-visit-1&clip=ready`, or press "Processing visit" in the `?toolbar=1` bar and wait five seconds) has a made-up track for the 640x360 fixture clip: an animal walks across and is named after a second, and a smaller one at the lower left reaches into the controls strip. `fixture-visit-4x3` (Back Door) and `fixture-visit-3x4` (Front Door, a portrait picture), at `/kestrel/visit?v=<id>`, do the same on `dev/fixtures/clip-4x3.mp4` and `clip-3x4.mp4`, which have a quarter-by-quarter grid drawn on them so a box can be checked by eye; the 4:3 one has a classifier percentage in its label, the others do not (the real one almost never sends it).
- **Real data.** Put a visit exactly as the plugin serves it (`detections` included) in `dev/fixtures/local/<visit id>.json` and its clip beside it as `dev/fixtures/local/<visit id>.mp4` (the folder is git-ignored), run `node dev/build.mjs` and `node dev/serve.mjs`, and open `/kestrel/visit?v=<visit id>`. The mock `kestrel/visit` answers with that file (its media links become the harness's own signed ones, the clip's always the visit's own) and `dev/serve.mjs` serves `/api/kestrel/media/clip/<visit id>` from the `.mp4`. Change `offsetMs` in the file and reload to try another offset.

## Rules that came out of measuring

- **Pressed feedback is a wash, or a veil over a picture, never a scale.** Changing a transform on press makes the
  browser create a graphics layer every time; a trace of the real panel showed 6-13 ms of main-thread work per press
  for it (species tile 16 ms), against 1.5-5 ms for a wash. The pressed rule also sets `transition: none` so the
  feedback lands in the first frame; the resting rule keeps a short colour transition for the release.
- **Timings are judged at the host's normal load, and the load is printed with them.** `perf-check` prints the one-minute load before and after each size
  and marks the size PROVISIONAL only when either is at or above `PERF_MAX_LOAD` (default 64; this host normally runs at 15-25, so waiting for a quiet
  window is not an option). Wall-clock numbers swing by 30-40 % between two runs minutes apart, so compare a change against the old build in alternating
  runs (A, B, A, B) and with `--repeats 7`, never against a number from another hour. To see what the panel itself costs regardless of load,
  trace a press and add up the main thread's thread-time
  (`UpdateLayoutTree`, `Layout`, `PrePaint`, `Paint`, `Layerize`, `Commit` within 160 ms of the `pointerdown`).
- Press timing never scrolls first (a centred scroll measures the new tiles' images, not the control), and every
  control press is preceded by an inert press in the same state, so "the machine is slow right now" is measured
  next to the control instead of at some other moment.
